**Источник брифа (обязательно прочитать целиком):** [`task3.md`](../../../../task3.md) в корне репозитория. Все входные данные, структура листов, роль и словарь — оттуда; этот prompt только кристаллизует исполнение для оркестратора.

## Суть задачи

Это третья часть тестового задания Head of PPC (Яндекс Директ, performance e-com), не фича продукта Polina. Нужен медиаплан на 12 месяцев для посадочной [ECCO Kids / мальчики](https://www.ecco.ru/kids/boys/), ГЕО РФ, месячная база бюджета 1 000 000 ₽ без НДС. Воронка до цели Метрики «Покупка на сайте»: показы → клики → (при необходимости) визиты = клики, если отказ отдельно не вводишь → покупки → выручка → ДРР (отдельный столбец «визиты» в контракте листов не требуется). Типы кампаний — только инструменты Директа (не сервисы вне Директа). Бенчмарки с явным источником; статистику кабинета ECCO не выдумывать. Результат — пять листов в указанной Google Таблице плюс локальная копия в `agent_work/` этой задачи и отдельный файл канонов медиапланирования.

## Проблема

Есть бриф и пустая таблица, нет согласованного сплита инструментов, сезонного бюджета и сквозной экономики до покупки. Без этого нельзя показать проверяющему предсказуемый ДРР и обоснование долей.

- **Слой B (репо / оператор, не в теле `task3.md`):** локальная копия в `{task_work_root}`, отдельный файл канонов, Google Drive MCP fallback, потолок ДРР как допуск. Обязательно для оркестратора этого репо; проверяющий Doc/Sheet может это не оценивать.

1. Google Таблица задания заполнена (цифры сходятся).
2. В репозитории — копия тех же листов (чтобы работа не зависела только от Drive).
3. Отдельный файл канонов: роль Head of PPC, словарь кабинета/справки, имена стратегий, правила ДРР/НДС.

Горизонт: **сентябрь 2026 — август 2027** (следующий полный месяц от даты брифа). AOV и потолок ДРР — из открытых источников (цены ECCO Kids / e-com обувь / детские товары РФ), явно как допущения.

## Цели

1. Зафиксировать допущения: бюджет без НДС, НДС отдельным столбцом при необходимости, AOV, сезонность детской обуви РФ (школьный сезон, зима, праздники, межсезонье) — бюджет месяца можно перераспределять внутри года, база ~1 млн ₽/мес без НДС; если месяц отклоняется от 1 млн — почему; сумма за год сходится; бенчи CTR / CPC / CR в покупку / CPA / ДРР, столбец «источник бенча» (предположение или статья+ссылка). Потолок ДРР — явное допущение из открытых обзоров (дата + ссылка в «Допущениях»), слой B.
2. Предложить 4–7 типов кампаний Директа: доли кампаний обосновываются нишей (родители, бренд ECCO, сезон, обучение стратегий) **сначала**; доля % и ₽, роль в воронке, стратегия из справки («Максимум конверсий», «Максимум кликов», «Максимум кликов с ручными ставками», «Максимум прибыли» — без разговорных подмен), кратко бренд / небренд / ретаргетинг / сети если используются. Потолок ДРР — sanity-check: если сводный ДРР выше потолка — объяснить отклонение или скорректировать бенчи/сезон, **не** подгонять доли ради красивого %.
3. **Gate перед сеткой:** файл канонов медиапланирования готов до заполнения «Медиаплан год» и сводок — роль Head of PPC vs Senior, полный словарь кабинета: тип кампании, места показа Поиск/РСЯ, условие показа, стратегия, ставка, цена конверсии, недельный бюджет, CTR, CPC, CR, CPA, ДРР, расход, покупки, выручка (компактный чеклист, без эссе из брифа).
4. Построить лист «Медиаплан год»: месяц × кампания (и стратегия); столбцы: бюджет, показы, CTR, клики, CPC, расход, CR покупка, покупки, AOV, выручка, CPA, ДРР. Внутри месяца — разбивка по типам и стратегиям. Если месяц ≠ 1 млн — почему; сумма за год сходится.
5. Листы «Сводка месяц» и «Сводка год»: итоги; общий ДРР / покупки / выручка. Сумма бюджетов кампаний = бюджет месяца; год = сумма месяцев.
6. Заполнить [Google Таблицу результата](https://docs.google.com/spreadsheets/d/1A31rkQ9JkJ3Bet8coGxcXw22bwFhqq4Xk7_GQxtdc8c/edit?gid=0#gid=0) и положить копию в `{task_work_root}` (не `backend/`, не `web/`).
7. Написать отдельный файл канонов медиаплана (не считать канон task2 достаточным) — до шага 4 (gate, см. п. 3).

## Ограничения

- **Нельзя ломать:** смысл брифа в `task3.md`; формулу ДРР (расход без НДС / выручка); разделение без НДС и с НДС.
- **Обязательно сохранить:** язык справки и кабинета; ЕПК = тип кампании, товарное/ТГО = тип объявления; автостратегии и цель «Покупка на сайте» по умолчанию; ручные ставки только если иначе нельзя объяснить логику.

## Риски и неясности

- Google Drive MCP: `needsAuth` — оркестратор не должен считать облачную таблицу единственным deliverable.

**Декомпозиция (два уровня):**
